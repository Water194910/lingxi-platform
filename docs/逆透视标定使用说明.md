# 四点逆透视标定

灵犀平台默认使用干净原图，标定只作用于上位机，不修改车辆算法。

## 棋盘格如何使用

黑白相间的棋盘格标定板可以用，但不能仅凭“有棋盘格”就获得准确地面尺度。

1. 固定车载摄像头的高度、俯仰角、焦点和分辨率。把棋盘格平放在与赛道同一平面上，避免翘曲；拍清全部要选的角点。
2. 测量每格边长。选棋盘中一个矩形的四角，宽=横向跨越的格数×格边长，长=前后跨越的格数×格边长。计算的是格子间隔数；不要把内角点个数直接当格数，也不要误用带白边的整张纸尺寸。
3. 先用灰度模式定位角点。在视觉工作台点“逆透视”，或在“采集”页点“四点逆透视”；窗口会复制当前干净图，后台接收继续，选点时图像不会移动。
4. 按 **远左→远右→近右→近左** 点击。矩形在原图中通常呈梯形，这是透视效果。选四个准确角点，尽量让矩形覆盖实际关注的道路区域；不要选纸上的阴影角。
5. 填写这四角围成区域的实测宽、长（厘米），再填像素/厘米，点“生成俯视图”。输出上方为远端，下方为近端，横纵近似同一物理尺度；栅格取整有不到一像素的误差。输出每边限2～1024像素。
6. 二值模式使用最近邻以保留0/255；灰度模式使用双线性插值。未拿到实测尺寸时不生成所谓真实尺度标定；尺寸栏不预填猜测值。
7. “保存标定”保存四点、尺寸与双向矩阵；“导出原图+俯视图”保存 `raw.png`、`bird.png`、`calibration.json`、`frame.json`。点选标记不写入这些图。新实时帧需重新打开实验窗口；载入同一标定可用于姿态与分辨率均未变的灰度或二值图。

当前只转换四角内的地面区域，不承诺矩形外道路的精度。单应变换不自动消除镜头畸变；棋盘格拍多个姿态进行镜头内参/畸变标定是另一个步骤。如果直线明显弯曲，后续应先去畸变再做平面逆透视。

## 验证和后续

在选四角以外，再用棋盘内部多处角点或地面已知距离检查俯视图：平行线是否平行，不同位置的同长线段是否接近等长。仅看到四角被拉成矩形不代表全场标定合格。

先完成灰度/二值同场景验证，再考虑把边界点映射到地面坐标做补线、环岛和十字分析。此次没有替换板端巡线、补线或电机控制。摄像头移动、分辨率改变或图像裁剪后须重新标定；相同尺寸并不能证明姿态没变。

离线复用（在仓库根目录运行）：

```powershell
python -m zf_ai_bridge.perspective --input frames/raw.png --calibration frames/perspective.local.json --out frames/bird.png
# 二值图追加 --binary
```

运行期图片和标定保存在所选数据目录，不提交Git；共享参数时另行整理已确认的标定与安装条件。
