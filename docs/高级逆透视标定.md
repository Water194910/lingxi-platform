# 高级逆透视标定

入口：灵犀的“图像分析 → 高级逆透视”，或图像工具栏“高级标定”。先接收或导入一张 **188×120干净原图**。其他尺寸可使用原有“四点逆透视”，高级工具不会强行缩放。

## 先测量，再选点

1. 固定相机高度、俯仰角、焦点和分辨率。把矩形平放在赛道平面，测量实宽、实长，单位统一为 **毫米**。棋盘格可选跨多个格子的矩形，不计纸边或阴影。
2. 选样本槽位，点“取当前帧”，或导入原始PNG/BMP/JPEG。取当前帧取灵犀当前工作图；历史帧锁定时也可以取图。取图后冻结，实时收图继续。
3. 填“参考点到近边距离”：从同一个固定参考点，沿地面到矩形近边的距离。填0表示这个参考点就在近边，后续样本仍要用同一参考点。
4. 按 **近左 → 近右 → 远左 → 远右** 点击。选错时可选“下一点”重新点击，或拖动已有圆点；x、y数值框支持精确坐标。原有四点工具的点序不同，不要混用。
5. 实测长宽已知时，一组完整样本即可计算。推荐添加不同距离的两到三组样本，勾选“此样本参与拟合”，检查各组误差。每组需要对应原图，不能将同一张图片当成不同距离。

多组采集时，相机保持不动，将**同一个矩形**沿同一中心线向前后平移，宽度、长度、方向保持一致。不能把相机重新摆放后的图混在一起。若不知道矩形长度，可选“用多组距离估算”，至少两组不同实测距离；实测长度通常更可靠。

## 滑条和数值框

每项可拖滑条粗调，也可填精确数值，二者联动。暂时清空或输入不完整数值时显示提示，不偷偷改成最小值，也不允许导出旧结果。

- **实测宽度/长度/近边距离（mm）**：真实测量值；不要仅为让预览好看而修改。
- **矩形显示宽度（px）**：鸟瞰中的缩放大小。值越大，固定188×120画幅可见的地面范围越小。
- **底行对应距离（mm）**：鸟瞰最底行到同一参考点的地面距离；用于选择前后观察区域。
- **横向中心（px）**：矩形中心线在鸟瞰图中的横向位置。

修改后约220ms自动提交后台计算；快速拖动时只采用最后一次有效结果。参数错误或地平线穿过输出区域时提示调整。左侧内容过长可滚动，深浅主题与主窗口同步。

## 验证与实时预览

右图默认变换当前冻结样本。“鸟瞰视图 → 用最新实时原图预览鸟瞰”只更新右图；左侧标定样本不会被覆盖。预览轮询不是图传帧率统计，不保证30fps显示。

总体RMS与各组误差使用**原图像素**。误差小只说明所选点拟合得好；一组四角误差接近0也不证明实车标定准确。请用未参与拟合的已知距离和直线验证，检查不同位置的同长线段、平行线及镜头畸变。当前不自动做镜头去畸变。

鸟瞰采用最近邻，保留原始灰度值与二值0/255。无对应原图的区域在预览中显示粉色；导出鸟瞰以白色填充，并附独立有效掩码。无效白色区域不能被算法当成道路。

## 保存和导出

- “保存标定”生成JSON与同名 `.frames` 原图文件夹。一起移动/分享，原图不带网格或点选标记。
- “载入标定”支持本工具JSON，以及所提供离线IPM工具的 `mode=points/matrix` JSON。缺少原图时先重新导入对应样本；不自动缩放。原有四点JSON使用“四点逆透视”载入。
- 手动矩阵模式使用 **H_inv（鸟瞰→原图）**。支持9个数字或C矩阵；该模式不会让视图滑条暗中改写矩阵，物理尺度由矩阵提供者确认。
- “导出结果”生成独立文件夹：标定JSON、原始样本、鸟瞰样本图、`valid-mask.png`、`ipm_lut.h`。掩码白=有效、黑=无效。不会覆盖、编译或烧录车辆工程。

`ipm_lut`：鸟瞰像素→原图线性索引 `y*188+x`；`ipm_point_lut`：原图像素→打包鸟瞰坐标 `(y<<8)|x`。两张表都以65535表示无效，使用前必须判断。表数据合计90,240字节，板端需评估只读存储、内存和编译布局，不能直接假定适合任意工程。边线查表只提供坐标映射，不代替补线、环岛或十字算法。

相机姿态、焦距、分辨率、裁剪或安装变化后重新标定。实车赛道、灰度与二值同场景验证仍需现场完成。
